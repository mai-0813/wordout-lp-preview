# WordOut LP Preview

このリポジトリは、WordOut の LP（ランディングページ）を静的サイトとして管理するためのプロジェクトです。

## 概要

- HTML / CSS / JavaScript のみで構成
- フレームワークやビルドツールは不要
- ローカルで簡単にプレビュー可能
- 画像やスタイル、スクリプトを分離して保守しやすい構成に整理済み

## ディレクトリ構成

```text
.
├── index.html        # ページ本体
├── styles.css        # 共通スタイル
├── js/
│   ├── utils.js      # 共通ヘルパー
│   ├── site.js       # 共通のページ動作
│   ├── hero-toggle.js
│   ├── feature-lightbox.js
│   ├── header.js
│   └── format-slider.js
├── img/              # 画像アセット
└── README.md         # このドキュメント
```

## ローカルプレビュー

ブラウザで直接 [index.html](index.html) を開いても表示できますが、ローカルサーバー経由の方がより実際の環境に近い挙動になります。

### 例: Python でローカルサーバーを起動

```bash
cd /Users/meitec-yagisawa/github/wordout-lp-preview
python3 -m http.server 8000
```

その後、ブラウザで次の URL を開いてください。

```text
http://localhost:8000
```

## 編集時のポイント

### HTML

- ページ構造の定義は [index.html](index.html) で管理
- 画像や CSS、JS の読込は外部ファイルに分離済み
- コンテンツの修正はここで行うのが基本

### CSS

- 見た目の定義は [styles.css](styles.css) に集約
- クラス名の命名がわかりやすいよう、セクション単位で管理しやすい構造を意識

### JavaScript

- 共通処理は [js/utils.js](js/utils.js) に置く
- 各ファイルの役割を分離しているため、修正範囲の特定がしやすい
- 画面の振る舞いを追加する場合は、既存モジュールの責務に合わせて配置する

## 今の整理方針

このプロジェクトの状態は、AI 生成物を「運用可能な静的サイト」に整理する過程としてはかなり良い状態です。

特に以下はすでに整理済みです。

- インライン CSS の分離
- インライン JS の分離
- base64 画像の実ファイル化
- JavaScript の責務分離
- 共通ユーティリティの集約

## 編集履歴の管理

本プロジェクトでは、変更内容を [docs/HISTORY.md](docs/HISTORY.md) に記録する運用とします。

- 変更の背景
- 実施した修正内容
- 影響範囲や注意点
- 以後の運用方針

上記を簡潔に残すことで、プロジェクトの経緯を後から追いやすくします。

README は利用者向けの入口として扱い、履歴の詳細は [docs/HISTORY.md](docs/HISTORY.md) に集約する設計です。

実務資料として完成する前に、以下を確認しておくと運用しやすくなります。

- README の説明が現状と一致している
- 履歴が [docs/HISTORY.md](docs/HISTORY.md) に整理されている
- 役割ごとにファイルが分かれている
- 不要なコメントや重複記述が残っていない

この確認が完了した後、次は `/init` を実行して初期化と標準化を行うのが適切です。
